\# Shift Dynamics - Git and Pull Request Workflow



\## Branch Strategy



The main branch contains the stable project version.



Each team member should work on a separate feature branch.



Example:



feature/backend-authentication

feature/frontend-dashboard

feature/database-schema

feature/testing-authentication



\## Development Workflow



1\. Update local main branch.

2\. Create or switch to the assigned feature branch.

3\. Implement the assigned work.

4\. Test the changes.

5\. Commit the changes with a meaningful commit message.

6\. Push the feature branch.

7\. Create a pull request.

8\. Request review.

9\. Fix review issues if required.

10\. Merge after approval and successful testing.



\## Pull Request Requirements



Each PR should contain:



\- Clear title

\- Description of changes

\- Related task/requirement

\- Testing information

\- Any known limitations



\## Project Manager Responsibilities



The Project Manager monitors branches and pull requests,

coordinates reviews, checks task completion, and helps ensure

that changes are integrated safely.



\## Important Rule



Do not directly push development work to main unless the team

has explicitly agreed to do so.
